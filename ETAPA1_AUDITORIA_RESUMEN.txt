## 3. DECISIONES DE SEGURIDAD CRÍTICAS

### 3.1 Función SECURITY DEFINER
- Schema: _private (no expuesto públicamente)
- search_path: SET a '' (vacío, previene inyección de schema)
- Referencias: Todas con prefijo explícito (public.family_members)
- Permisos: Solo EXECUTE para rol authenticated
- Schema _private: REVOKE ALL desde PUBLIC y authenticated

### 3.2 Row Level Security
- Habilitado en las 8 tablas públicas
- Políticas limitadas exclusivamente al rol 'authenticated'
- Rol 'anon' sin acceso a datos familiares
- family_members: INSERT/UPDATE/DELETE bloqueados (solo lectura para miembros)

### 3.3 Protección de Credenciales
- .env en .gitignore
- Solo variables VITE_* en frontend
- Sin service_role ni claves secretas en código
- .env.example como única plantilla

## 4. ESTRUCTURA DE BASE DE DATOS

### Tablas Creadas (8)
1. families - Información familiar básica
2. profiles - Datos de usuario (vinculado a auth.users)
3. family_members - Relación usuarios-familias (con rol)
4. events - Controles, vacunas, citas
5. expenses - Gastos registrados
6. products - Inventario de productos esenciales
7. shopping_items - Lista de compras
8. tasks - Tareas y trámites

### Restricciones CHECK
- expenses.amount_clp >= 0
- products.current_stock >= 0
- products.minimum_stock >= 0
- shopping_items.quantity > 0

### Índices
- Todos los foreign keys indexados
- family_id indexado en todas las tablas funcionales
- user_id indexado en profiles y family_members
